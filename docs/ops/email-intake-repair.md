# Incomplete historical email imports (#973)

No automatic repair runs with this change. Do not reimport emails, rewrite Applications or run this against staging/production without separate authorization. The purged original email cannot recover a historical missing URL; a human must supply verified public evidence or leave it skipped.

`planEmailOfferRepairs` (`apps/worker/src/email-intake/repair-plan.ts`) is a read-only proposal API, with no database, capture, queue or Application write interface. It accepts at most 25 distinct operator-selected existing Job Offer identities, their verified source URLs and the affected active Profiles. It skips private offers, missing links, unread sources and postings older than 30 days; the same polite reader blocks Forbidden sites and unsafe redirects. It returns source details and recalculated per-Candidate Profile assignments for those same identities. It never searches for correspondence, invents links, creates replacement offers or changes a dossier. Proposals contain private Profile identifiers: keep them in the authorized maintenance environment, never in issues or PR artifacts.

1. Under explicit authorization, inventory incomplete **shared alert** imports and all affected email arrivals/Applications. Select a batch of at most 25; snapshot existing content hash, source URL and assignment/update versions. Require verified source evidence and list every affected Profile. Review scope before any writes.
2. Generate a proposal with the planner. Review the field differences, stated publication date, source readability, score differences and every assignment. Missing source fields remain unknown. Re-run the same dry-run safely if interrupted; there are no writes.
3. A separately authorized maintenance transaction can update the existing Job Offer identity and explicitly approved derived scores/assignments only if the snapshot versions still match. Preserve visibility, arrival/dismissal state and dossier identity; never create new Applications, change a Candidate's later Profile decision or overwrite Tailored Documents. Record source reading Provenance and an audit reference, enforce one idempotency key per offer/source-content hash, and roll back the whole item on conflict. This write adapter is intentionally not shipped or invoked here: it depends on the inventory and approved scope.
4. Re-read the same identities and verify the approved differences and audit record. A repeat application must be a no-op. Stop the batch on any unexpected scope or version difference.

Tests cover the read-only planner's identity preservation, cap, duplicate rejection, skips and source failure. Worker regressions separately prove enrichment precedes Profile scoring. No historical repair was performed during development.

Privacy review: this reuses the existing public posting reader and public `offer_analysis` task; no email correspondence or Candidate/Profile data enters that path, and no new processor or recipient is introduced. The register clarifies this boundary. No new Legal Text issue is required for that unchanged disclosure boundary.
